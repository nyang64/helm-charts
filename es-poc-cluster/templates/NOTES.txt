PRE-REQUISITE -- TLS secret for the Istio ingress gateway (platform team)
-------------------------------------------------------------------------
  The Gateway CRD references a TLS secret in the istio-system namespace.
  This must be created BEFORE the gateway will serve external HTTPS traffic.
  It is out of scope for this chart -- coordinate with your platform team.

  Option A -- from an existing cert/key pair:
  kubectl create secret tls {{ .Values.istio.gateway.tls.credentialName }} \
    --cert=tls.crt --key=tls.key \
    -n istio-system

  Option B -- via cert-manager (targeting istio-system):
  kubectl apply -f - <<EOF
  apiVersion: cert-manager.io/v1
  kind: Certificate
  metadata:
    name: {{ .Values.istio.gateway.tls.credentialName }}
    namespace: istio-system
  spec:
    secretName: {{ .Values.istio.gateway.tls.credentialName }}
    dnsNames: ["{{ .Values.istio.gateway.hostname }}"]
    issuerRef:
      name: <your-cluster-issuer>
      kind: ClusterIssuer
  EOF
{{- end }}

--------------------------------
{{- if .Values.istio.gateway.hostname }}
  External URL (via Istio Gateway -- no port-forward needed):
  export ES_URL=https://{{ .Values.istio.gateway.hostname }}

  The elastic superuser authenticates via the native realm -- it is always

  export ELASTIC_PASSWORD=$(kubectl get secret {{ include "es-poc-cluster.fullname" . }}-bootstrap \
    -n {{ .Release.Namespace }} \
    -o jsonpath='{.data.ELASTIC_PASSWORD}' | base64 -d)
  {{- end }}

  Verify cluster health:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \

STEP 3 -- Verify AD integration
-------------------------------
  AD connectivity failure does NOT affect the elastic superuser -- only AD
  users are locked out. The cluster itself continues to operate normally.

  Authenticate as an AD user to confirm group-to-role mapping works:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u "DOMAIN\\your-ad-username:your-ad-password" \
    "$ES_URL/_security/_authenticate?pretty"
  # The "roles" array in the response must contain the expected mapped role.
  # If AD is unreachable: this returns 401; elastic still returns 200.

  To check which roles an AD user would receive without their password:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X POST "$ES_URL/_security/user/DOMAIN%5Cyour-ad-username/_has_privileges" \
    -H "Content-Type: application/json" -d '{"index":[{"names":["*"],"privileges":["read"]}]}'
{{- end }}


STEP {{ if .Values.ad.enabled }}4{{ else }}3{{ end }} -- Create an application API key
--------------------------------------------------------------------------------------
  Applications authenticate with API keys, not user credentials. Keys are
  scoped to exact permissions, have no AD dependency at runtime, and can be
  rotated without changing app configuration.

  Create a key scoped to knowledge-base read/write (run as elastic):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X POST "$ES_URL/_security/api_key" \
    -H "Content-Type: application/json" -d '
    {
      "name": "{{ .Values.clusterName }}-app-key",
      "role_descriptors": {
        "knowledge_base_rw": {
          "indices": [{
            "names":      ["knowledge-base*"],
            "privileges": ["read", "write", "create_index"]
          }]
        }
      }
    }'
  # Response: { "id": "abc", "api_key": "xyz", ... }
  # Encode:    echo -n "abc:xyz" | base64

  Store in a K8s secret in the application namespace:
  kubectl create secret generic es-api-key \
    --from-literal=ES_API_KEY="<base64(id:api_key)>" \
    -n <app-namespace>

  Applications set this header on every request -- no username or AD lookup:
  Authorization: ApiKey <base64(id:api_key)>

STEP {{ if .Values.ad.enabled }}5{{ else }}4{{ end }} -- Load the embedding model ({{ .Values.ml.modelId }})
-----------------------------------------------------------------------------------------------------------
  Apply the model-loader Job (runs once; retries up to 5 times if ES is not ready).
  ml.installJob=true is required -- the Job is off by default to prevent it running
  before the cluster is healthy:
  kubectl apply -f <(helm template {{ .Release.Name }} . \
    --show-only templates/model-loader-job.yaml \
    --set ml.installJob=true) \
    -n {{ .Release.Namespace }}

  Watch progress:
  kubectl logs -f job/{{ include "es-poc-cluster.fullname" . }}-model-loader \
    -n {{ .Release.Namespace }}

  Wait until the log shows the model started successfully.

  Note: eland normalises the model ID for ES storage -- forward slashes become
  double underscores:  {{ .Values.ml.modelId }} -> {{ .Values.ml.modelId | replace "/" "__" }}

  To swap models later, delete the Job then re-apply with a new ml.modelId:
  kubectl delete job {{ include "es-poc-cluster.fullname" . }}-model-loader \
    -n {{ .Release.Namespace }}


STEP {{ if .Values.ad.enabled }}6{{ else }}5{{ end }} -- Create an inference endpoint
--------------------------------------------------------------------------------------
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X PUT "$ES_URL/_inference/text_embedding/{{ .Values.ml.modelId | replace "/" "-" | lower }}" \
    -H "Content-Type: application/json" -d '
    {
      "service": "elasticsearch",
      "service_settings": {
        "model_id": "{{ .Values.ml.modelId | replace "/" "__" }}",
        "num_allocations": {{ .Values.ingest.replicas }},
        "num_threads": 2
      }
    }'


STEP {{ if .Values.ad.enabled }}7{{ else }}6{{ end }} -- Create an index with semantic_text mapping
----------------------------------------------------------------------------------------------------
  Adjust field names to match your document schema. The body field uses
  semantic_text -- ES automatically chunks and embeds it on every write.

  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X PUT "$ES_URL/knowledge-base" \
    -H "Content-Type: application/json" -d '
    {
      "mappings": {
        "properties": {
          "title":      { "type": "text" },
          "body":       { "type": "semantic_text",
                          "inference_id": "{{ .Values.ml.modelId | replace "/" "-" | lower }}" },
          "source_url": { "type": "keyword" },
          "created_at": { "type": "date" }
        }
      }
    }'


STEP {{ if .Values.ad.enabled }}8{{ else }}7{{ end }} -- Smoke test
-------------------------------------------------------------------
  Index a document (ES chunks and embeds the body field automatically):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X POST "$ES_URL/knowledge-base/_doc" \
    -H "Content-Type: application/json" -d '
    {
      "title": "Smoke test document",
      "body": "Elasticsearch semantic_text automatically chunks and embeds this text using the deployed model.",
      "source_url": "https://example.com/test",
      "created_at": "{{ now | date "2006-01-02" }}"
    }'

  Wait ~5 seconds for the embedding to complete, then search:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -u elastic:$ELASTIC_PASSWORD \
    -X POST "$ES_URL/knowledge-base/_search?pretty" \
    -H "Content-Type: application/json" -d '
    {
      "query": {
        "semantic": {
          "field": "body",
          "query": "how does semantic search work?"
        }
      }
    }'

  A hit with a non-zero score confirms the full pipeline is working.
