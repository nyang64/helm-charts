STEP {{ $step }} -- Create an application API key
-------------------------------------------------
  Applications authenticate with API keys, not user credentials. Keys are
  scoped to exact permissions, have no realm dependency at runtime, and can be
  rotated without changing app configuration.

  Create a key scoped to knowledge-base read/write (run as elastic):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_security/api_key" \
    -H "Content-Type: application/json" -d '
    {
      "name": "{{ .Values.clusterName }}-app-key",
      "role_descriptors": {
        "knowledge_base_rw": {
          "indices": [{
            "names":      ["knowledge-base*"],
            "privileges": ["read", "write", "create_index"]
          }]
        }
      }
    }'
  # Response: { "id": "abc", "api_key": "xyz", ... }
  # Encode:    echo -n "abc:xyz" | base64

  Store in a K8s secret in the application namespace:
  kubectl create secret generic es-api-key \
    --from-literal=ES_API_KEY="<base64(id:api_key)>" \
    -n <app-namespace>

  Applications set this header on every request -- no username or password lookup:
  Authorization: ApiKey <base64(id:api_key)>
{{- end }}

STEP {{ $step }} -- Register snapshot repository and create SLM policy
----------------------------------------------------------------------
  {{- if and (eq .Values.snapshot.repository.type "s3") .Values.snapshot.repository.s3.credentialsSecret }}
  S3 credentials are loaded into the ES keystore automatically by the keystore-init
  container on every pod start (from secret {{ .Values.snapshot.repository.s3.credentialsSecret }}).
  S3 client settings (endpoint, path_style_access, protocol) are already in
  elasticsearch.yml -- no manual keystore provisioning needed.
  {{- else if and (eq .Values.snapshot.repository.type "s3") .Values.snapshot.repository.s3.irsa.roleArn }}
  IRSA configured -- ES pods assume the IAM role via the projected service account
  token. No static credentials or keystore provisioning needed.
  {{- end }}

  1. Register the {{ .Values.snapshot.repository.type | upper }} repository (run once after cluster is healthy):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X PUT "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}" \
    -H "Content-Type: application/json" -d '
    {
      "type": "{{ .Values.snapshot.repository.type }}",
      "settings": {
        {{- if eq .Values.snapshot.repository.type "s3" }}
        "bucket": "{{ .Values.snapshot.repository.s3.bucket }}",
        "base_path": "{{ .Values.snapshot.repository.s3.basePath }}"
        {{- else if eq .Values.snapshot.repository.type "gcs" }}
        "bucket": "{{ .Values.snapshot.repository.gcs.bucket }}",
        "base_path": "{{ .Values.snapshot.repository.gcs.basePath }}"
        {{- else if eq .Values.snapshot.repository.type "azure" }}
        "container": "{{ .Values.snapshot.repository.azure.container }}",
        "base_path": "{{ .Values.snapshot.repository.azure.basePath }}"
        {{- end }}
      }
    }'

  2. Verify (triggers a write + read test against the bucket):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/_verify?pretty"

  3. Create the SLM policy:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X PUT "$ES_URL/_slm/policy/{{ .Values.snapshot.repository.name }}-daily" \
    -H "Content-Type: application/json" -d '
    {
      "schedule": "{{ .Values.snapshot.slm.schedule }}",
      "name": "<daily-snap-{now/d}>",
      "repository": "{{ .Values.snapshot.repository.name }}",
      "config": { "include_global_state": false },
      "retention": {
        "expire_after": "{{ .Values.snapshot.slm.retention.expireAfter }}",
        "min_count": {{ .Values.snapshot.slm.retention.minCount }},
        "max_count": {{ .Values.snapshot.slm.retention.maxCount }}
      }
    }'

  4. Run an immediate snapshot to verify end-to-end:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_slm/policy/{{ .Values.snapshot.repository.name }}-daily/_execute?pretty"

  5. Restore procedure (disaster recovery):
  # List available snapshots:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/_all?pretty"
  # Restore (close or delete the target indices first if they exist):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/<snap-name>/_restore?pretty" \
    -H "Content-Type: application/json" -d '{"include_global_state": false}'
{{- end }}

STEP {{ $step }} -- Integrate Kibana
------------------------------------
  Kibana authenticates to ES using a service account token -- a long-lived credential
  scoped to the built-in elastic/kibana service account (kibana_system privileges).
  Unlike a password, the token is stored in ES as a SHA-256 hash and can be revoked
  per-instance without touching any password. ES supports multiple tokens for the same
  service account, so you can rotate by creating a new one and deleting the old --
  zero-downtime credential rotation.

  1. Create the token (run as elastic after cluster is healthy):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_security/service/elastic/kibana/credential/token/kibana-1?pretty"
  # SAVE the "value" field from the response immediately.
  # ES stores only the hash -- the plaintext token is shown exactly once.
  # To rotate later: POST a new token name (kibana-2, etc.) then DELETE the old one.

  2. Store the token as a K8s secret in the Kibana namespace:
  kubectl create secret generic kibana-es-token \
    --from-literal=token="<value-from-above>" \
    -n {{ .Values.kibana.namespace }}

  {{- if and .Values.tls.enabled (not .Values.istio.enabled) }}

  3. Copy the ES CA certificate to the Kibana namespace (Kibana must verify ES TLS):
  kubectl get secret {{ include "es-poc-cluster.tlsSecretName" . }} \
    -n {{ .Release.Namespace }} \
    -o jsonpath='{.data.ca\.crt}' | base64 -d | \
    kubectl create secret generic es-ca \
      --from-file=ca.crt=/dev/stdin \
      -n {{ .Values.kibana.namespace }}

  {{- end }}
  {{- if .Values.istio.enabled }}

  Istio: add {{ .Values.kibana.namespace | quote }} to istio.allowedNamespaces in your
  values overlay so the AuthorizationPolicy permits Kibana pods to reach ES on port 9200:
    istio:
      allowedNamespaces: [{{ .Values.kibana.namespace | quote }}]

  {{- end }}

  4. Minimal elastic/kibana chart values:
  # helm repo add elastic https://helm.elastic.co
  # helm install kibana elastic/kibana -f kibana-values.yaml -n {{ .Values.kibana.namespace }}
  #
  # kibana-values.yaml:
  elasticsearchHosts: "{{ include "es-poc-cluster.httpScheme" . }}://{{ include "es-poc-cluster.fullname" . }}-ingest.{{ .Release.Namespace }}.svc:9200"
  extraEnvs:
    - name: ELASTICSEARCH_SERVICEACCOUNTTOKEN
      valueFrom:
        secretKeyRef:
          name: kibana-es-token
          key: token
  {{- if and .Values.tls.enabled (not .Values.istio.enabled) }}
  secretMounts:
    - name: es-ca
      secretName: es-ca
      path: /usr/share/kibana/config/certs/es-ca
  kibanaConfig:
    kibana.yml: |
      elasticsearch.ssl.certificateAuthorities: [/usr/share/kibana/config/certs/es-ca/ca.crt]
      elasticsearch.ssl.verificationMode: certificate
  {{- end }}

  5. Verify the token works before starting Kibana:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }} \
    -H "Authorization: Bearer <value-from-step-1>" \
    "$ES_URL/_security/_authenticate?pretty"
  # Expected: username = "kibana", roles = ["kibana_system"]
{{- end }}

STEP {{ $step }} -- Load the embedding model ({{ .Values.ml.modelId }})
-----------------------------------------------------------------------
  Apply the model-loader Job (runs once; retries up to 5 times if ES is not ready).
  ml.installJob=true is required -- the Job is off by default to prevent it running
  before the cluster is healthy:
  kubectl apply -f <(helm template {{ .Release.Name }} . \
    -f environments/<your-env>.yaml \
    --show-only templates/model-loader-job.yaml \
    --set ml.installJob=true) \
    -n {{ .Release.Namespace }}

  Watch progress:
  kubectl logs -f job/{{ include "es-poc-cluster.fullname" . }}-model-loader \
    -n {{ .Release.Namespace }}

  Wait until the log shows the model started successfully.

  Note: eland normalises the model ID for ES storage -- forward slashes become
  double underscores:  {{ .Values.ml.modelId }} -> {{ .Values.ml.modelId | replace "/" "__" }}

  To swap models later, delete the Job then re-apply with a new ml.modelId:
  kubectl delete job {{ include "es-poc-cluster.fullname" . }}-model-loader \
    -n {{ .Release.Namespace }}
