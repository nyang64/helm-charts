-------------------------------------------------------------------------

STEP {{ $step }} -- Create an application API key
-------------------------------------------------
  Applications authenticate with API keys, not user credentials. Keys are
  scoped to exact permissions, have no realm dependency at runtime, and can be
  rotated without changing app configuration.

  Create a key scoped to knowledge-base read/write (run as elastic):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_security/api_key" \
    -H "Content-Type: application/json" -d '
    {
      "name": "{{ .Values.clusterName }}-app-key",
      "role_descriptors": {
        "knowledge_base_rw": {
          "indices": [{
            "names":      ["knowledge-base*"],
            "privileges": ["read", "write", "create_index"]
          }]
        }
      }
    }'
  # Response: { "id": "abc", "api_key": "xyz", ... }
  # Encode:    echo -n "abc:xyz" | base64

  Store in a K8s secret in the application namespace:
  kubectl create secret generic es-api-key \
    --from-literal=ES_API_KEY="<base64(id:api_key)>" \
    -n <app-namespace>

  Applications set this header on every request -- no username or password lookup:
  Authorization: ApiKey <base64(id:api_key)>
{{- end }}

STEP {{ $step }} -- Register snapshot repository and create SLM policy
----------------------------------------------------------------------
  {{- if .Values.snapshot.repository.s3.credentialsSecret }}
  S3 credentials are loaded into the ES keystore automatically by the keystore-init
  container on every pod start (from secret {{ .Values.snapshot.repository.s3.credentialsSecret }}).
  S3 client settings (endpoint, path_style_access, protocol) are already in
  elasticsearch.yml -- no manual keystore provisioning needed.
  {{- end }}

  Snapshot scope (include_global_state: false, no explicit feature_states):
    INCLUDED: all index data, mappings, settings, and aliases.
    EXCLUDED: .security-* feature state (users, roles, API keys, Kibana service
              tokens), ILM policies, index templates, ingest pipelines, component
              templates, and persistent cluster settings.
  This is a data-only backup. Security state and cluster configuration are NOT
  recoverable from these snapshots. Recreate them from IaC/secrets manager after
  restoring to a fresh cluster.

  1. Register the S3 repository (run once after cluster is healthy):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X PUT "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}" \
    -H "Content-Type: application/json" -d '
    {
      "type": "s3",
      "settings": {
        "bucket": "{{ .Values.snapshot.repository.s3.bucket }}",
        "base_path": "{{ .Values.snapshot.repository.s3.basePath }}"
      }
    }'

  2. Verify (triggers a write + read test against the bucket):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/_verify?pretty"

  3. Create the SLM policy:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X PUT "$ES_URL/_slm/policy/{{ .Values.snapshot.repository.name }}-daily" \
    -H "Content-Type: application/json" -d '
    {
      "schedule": "{{ .Values.snapshot.slm.schedule }}",
      "name": "<daily-snap-{now/d}>",
      "repository": "{{ .Values.snapshot.repository.name }}",
      "config": { "include_global_state": false },
      "retention": {
        "expire_after": "{{ .Values.snapshot.slm.retention.expireAfter }}",
        "min_count": {{ .Values.snapshot.slm.retention.minCount }},
        "max_count": {{ .Values.snapshot.slm.retention.maxCount }}
      }
    }'

  4. Run an immediate snapshot to verify end-to-end:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_slm/policy/{{ .Values.snapshot.repository.name }}-daily/_execute?pretty"

  5. Restore procedure:

  # List available snapshots:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/_all?pretty"

  5. Restore -- recover indices into the cluster:
  # Close or delete the target indices first if they already exist, then:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_snapshot/{{ .Values.snapshot.repository.name }}/<snap-name>/_restore?pretty" \
    -H "Content-Type: application/json" -d '{"include_global_state": false}'
  # NOTE: include_global_state:true cannot be used here -- the snapshot was taken
  # with include_global_state:false and does not contain global state.
  # After a full cluster loss, recreate users/roles/API keys from your secrets
  # manager and reapply IaC config before restoring data.
{{- end }}

STEP {{ $step }} -- Enable Kibana
----------------------------------
{{- if .Values.kibana.enabled }}
  Kibana is active in this release. Access it:
  kubectl rollout status deployment/{{ include "es-poc-cluster.fullname" . }}-kibana \
    -n {{ .Release.Namespace }}
  kubectl port-forward svc/{{ include "es-poc-cluster.fullname" . }}-kibana 5601:5601 \
    -n {{ .Release.Namespace }}
  # Open: http://localhost:5601 -- log in as elastic / <ELASTIC_PASSWORD>

  Token rotation (zero-downtime -- new token, update secret, delete old):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_security/service/elastic/kibana/credential/token/kibana-2?pretty"
  # Save the new "value", then update the secret:
  kubectl create secret generic {{ .Values.kibana.serviceAccountToken.existingSecret }} \
    --from-literal=token="<new-value>" \
    --dry-run=client -o yaml | kubectl apply -f - -n {{ .Release.Namespace }}
  # Upgrade to trigger restart (checksum/token-secret annotation detects the change).
  # Use --reuse-values to preserve kibana.enabled=true and other runtime settings;
  # without it, helm upgrade with the env file alone reverts Kibana to disabled if
  # kibana.enabled is not persisted in the overlay.
  helm upgrade {{ .Release.Name }} . -f environments/<your-env>.yaml --reuse-values -n {{ .Release.Namespace }}
  # Once Kibana is healthy with the new token, revoke the old one:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X DELETE "$ES_URL/_security/service/elastic/kibana/credential/token/kibana-1?pretty"
{{- else }}
  Kibana is included in this chart but not yet active (kibana.enabled=false).
  Complete these 3 steps after STEP 1 (ES healthy and all pods Ready):

  1. Create the ES service account token (run as elastic):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/_security/service/elastic/kibana/credential/token/kibana-1?pretty"
  # SAVE the "value" field from the response immediately.
  # ES stores only the SHA-256 hash -- the plaintext is shown exactly once.

  2. Create a K8s Secret with the token:
  kubectl create secret generic kibana-es-token \
    --from-literal=token="<value-from-step-1>" \
    -n {{ .Release.Namespace }}

  3. Upgrade the release to enable Kibana:
  helm upgrade {{ .Release.Name }} . \
    -f environments/<your-env>.yaml \
    --set kibana.enabled=true \
    --set kibana.serviceAccountToken.existingSecret=kibana-es-token \
    -n {{ .Release.Namespace }}

  Access Kibana after the rollout completes:
  kubectl port-forward svc/{{ include "es-poc-cluster.fullname" . }}-kibana 5601:5601 \
    -n {{ .Release.Namespace }}
  # Open: http://localhost:5601 -- log in as elastic / <ELASTIC_PASSWORD>

  See docs/kibana-setup.md for encryption keys (required for alerts and saved objects)
  and full token rotation instructions.

STEP {{ $step }} -- BYO vector: create a dense_vector index (external embedding service)
-----------------------------------------------------------------------------------------
  Vectors arrive pre-computed from an external embedding service. ES stores
  both the text and the vector, and handles kNN search.
  No inference endpoint or ML model is needed in this chart.

  1. Create an index with dense_vector mapping:
     Adjust dims to match your embedding model output (e.g. 384, 768, 1024).
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X PUT "$ES_URL/knowledge-base" \
    -H "Content-Type: application/json" -d '
    {
      "mappings": {
        "properties": {
          "text":       { "type": "text" },
          "vector":     { "type": "dense_vector", "dims": 3,
                          "index": true, "similarity": "cosine" },
          "source_url": { "type": "keyword" },
          "created_at": { "type": "date" }
        }
      }
    }'

  2. Index a document (client supplies the pre-computed vector):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/knowledge-base/_doc" \
    -H "Content-Type: application/json" -d '
    {
      "text":       "Elasticsearch stores and searches pre-computed vectors.",
      "vector":     [0.12, -0.34, 0.56],
      "source_url": "https://example.com/doc1",
      "created_at": "{{ now | date "2006-01-02" }}"
    }'

  3. kNN search (client pre-computes the query vector via the same embedding service):
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/knowledge-base/_search?pretty" \
    -H "Content-Type: application/json" -d '
    {
      "knn": {
        "field":        "vector",
        "query_vector": [0.11, -0.33, 0.55],
        "k":            10,
        "num_candidates": 100
      },
      "_source": ["text", "source_url"]
    }'

  4. Hybrid search -- combine kNN + BM25 restricted to a single source_url.
     The filter is applied to BOTH branches so only documents from that source appear:
  curl -sf{{- if and .Values.tls.enabled (not .Values.istio.enabled) }} -k{{- end }}{{ $curlAuth }} \
    -X POST "$ES_URL/knowledge-base/_search?pretty" \
    -H "Content-Type: application/json" -d '
    {
      "knn": {
        "field":        "vector",
        "query_vector": [0.11, -0.33, 0.55],
        "k":            10,
        "num_candidates": 100,
        "filter": { "term": { "source_url": "https://example.com/doc1" } }
      },
      "query": {
        "bool": {
          "must":   { "match": { "text": "vector search" } },
          "filter": { "term": { "source_url": "https://example.com/doc1" } }
        }
      }
    }'
